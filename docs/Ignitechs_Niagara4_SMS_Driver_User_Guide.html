1. Architecture Overview

The Ignitechs SMS Driver adds native, dependency-free SMS & mobile alert delivery to any Niagara 4 Supervisor or JACE station without requiring a serial port modem. All messages pass through a single background dispatcher with priority ordering, automatic multi-gateway failover, retry queue, hourly rate limiting, and duplicate suppression.

2. Step 1 — Install the Module & Trust the Certificate

Step 1.1: Copy ignitechsSms-rt.jar to Niagara Modules

  1. Copy dist\ignitechsSms-rt.jar from the module package folder into your Niagara installation's modules directory:
    C:\Niagara\Niagara-4.x.x.x\modules\ignitechsSms-rt.jar
  2. Close and restart Niagara Workbench and your Niagara Station (or Platform Daemon) so the module is loaded.

Step 1.2: Import the Ignitechs Root CA Certificate (Workbench & Platform)

  1. Workbench Trust Store (My Host): In Niagara Workbench, open My Host → Certificate Management (or Tools → Certificate Management), select the User Trust Store tab, click Import, select certs\IgnitechsRootCA.pem (or IgnitechsRootCA.cer) from the module package folder, and click OK.
  2. Platform / Station Trust Store (Platform): In the Nav tree, expand Platform → Certificate Management (or Station → Config → Services → PlatformServices → CertManagerService), open the User Trust Store tab, click Import, select certs\IgnitechsRootCA.pem, and click OK.
  3. Restart your Niagara Station from Platform → Application Director so the station trusts the signed module when adding SmsService.

Step 1.3: Open the ignitechsSms Palette

  1. In Niagara Workbench, open the Palette side bar (Window → Side Bars → Palette).
  2. Click the Open Palette folder icon in the Palette toolbar.
  3. Type ignitechsSms in the module filter, select ignitechsSms, and click OK.

3. Step 2 — Add SmsNetwork Under Drivers

  1. In the Nav tree, expand your station: Station (<StationName>) → Config → Drivers.
  2. From the ignitechsSms palette, drag SmsNetwork and drop it onto Drivers.
  3. Double-click SmsNetwork (or open its Ax Property Sheet) and review its settings:
Property Default Description
Enabled true Master enable for the SMS driver and background dispatch queue.
Site Name (Station Name) Friendly building/site name used for the {station} placeholder in SMS messages (e.g., Tower A BMS).
Time Format dd-MMM HH:mm Timestamp format used by the {time} placeholder in SMS messages.
Max Retries 3 Number of retry cycles after all enabled gateways fail for a message.
Retry Delay 0000h 01m 00s Wait time before retrying a failed message.
Max Messages Per Hour 120 Rate limit to prevent SMS storms during mass equipment faults (0 = unlimited).
Duplicate Suppression 0000h 02m 00s Identical text to the same phone number within this window is sent only once.
Gsm Friendly Text true Replaces smart quotes and degree symbols (° → deg) so messages fit in 160-char GSM-7 instead of 70-char Unicode.

4. Step 3 — Configure an Open-Source Internet SMS Gateway

Expand the Gateways folder inside the ignitechsSms palette. Drag one (or more) of the pre-configured internet gateways below and drop it directly onto SmsNetwork.

Option A (Recommended for Real Carrier SMS): TextBeeCloud — Open-Source Internet SMS Gateway

TextBee (https://textbee.dev | GitHub: vernu/textbee, MIT License) turns any Android phone with a SIM card into an internet-accessible REST SMS gateway (cloud or self-hosted Docker) with no port forwarding required.

  1. Create a free account at https://textbee.dev (or run the open-source TextBee Docker container) and install the TextBee Android app on an Android phone with an active SIM.
  2. Scan the QR code in the TextBee dashboard to link the phone, then copy your Device ID and API Key.
  3. In Niagara Workbench, drag TextBeeCloud from Palette → Gateways onto SmsNetwork.
  4. Open the Property Sheet of TextBeeCloud and set:
    • Preset: TextBee Cloud / Self-Hosted (Open-Source Internet SMS)
    • Url: https://api.textbee.dev/api/v1/gateway/devices/{username}/send-sms (pre-filled)
    • Headers: x-api-key: {password} (pre-filled)
    • Body: {"recipients":["{phone}"],"message":"{message}"} (pre-filled)
    • Username: Paste your TextBee Device ID
    • Password: Paste your TextBee API Key
  5. Click Save. Right-click TextBeeCloud → Actions → Send Test SMS, enter a phone number (e.g., +971501234567), and click OK.

Option B (Open-Source Cloud Relay): SmsGateCloud — Android SMS Gateway Cloud

Uses the open-source SMS Gateway for Android project (GitHub: capcom6/android-sms-gateway, Apache-2.0 License) in Cloud Server mode (https://api.sms-gate.app).

  1. Install the open-source SMS Gateway for Android APK on an Android phone, select Cloud Server mode, and toggle the server Online.
  2. Note the Username and Password displayed on the app home screen.
  3. Drag SmsGateCloud from Palette → Gateways onto SmsNetwork.
  4. In its Property Sheet, enter the app's Username and Password (Basic Auth is already set to true) and click Save.

Option C (Zero SIM Card & Zero Cost): NtfyInternetAlert — Open-Source ntfy.sh Push Service

ntfy (https://ntfy.sh | GitHub: binwiederhier/ntfy, Apache-2.0/GPLv2) is a 100% free, open-source internet pub/sub mobile notification service. It requires no SIM card, no modem, and no account.

  1. Install the free open-source ntfy app on Android or iOS (or open https://ntfy.sh/app in a browser) and subscribe to a unique secret topic name, e.g., ignitechs-supervisor-alarms-9812.
  2. Drag NtfyInternetAlert from Palette → Gateways onto SmsNetwork.
  3. In its Property Sheet, set Username to your topic name (ignitechs-supervisor-alarms-9812) and click Save.
  4. Right-click NtfyInternetAlert → Actions → Send Test SMS — every subscribed phone immediately receives a high-priority alert with the recipient phone number in the title and the SMS text in the body.

Tip — Automatic Multi-Gateway Failover: You can place multiple gateways under SmsNetwork! Set Priority = 1 on your primary SMS gateway (e.g., TextBeeCloud) and Priority = 2 on a backup gateway (e.g., NtfyInternetAlert or SmppGateway). If Gateway 1 cannot reach the internet or fails, SmsNetwork automatically fails over to Gateway 2.

5. Step 4 — Add Contacts & Groups (Address Book)

Step 4.1: Add Contacts (SmsNetwork → Contacts)

  1. In the Nav tree, expand SmsNetwork → Contacts.
  2. Drag SmsContact from the ignitechsSms palette and drop it into Contacts. Name it after the person (e.g., Ahmad_FM).
  3. Double-click the contact to open its Property Sheet:
    • Enabled: true
    • Phone Number: Enter in international format (e.g., +971501234567). Spaces/dashes are normalized automatically.
    • Description: Optional role note (e.g., Facility Manager).
    • On Duty Days: Select which days of the week this person should receive SMS alerts (default: all 7 days).
    • On Duty Time: Time window when this contact is on duty (default: All Hours 00:00–24:00).
  4. Right-click the contact → Actions → Send Test SMS to send a test message directly to that contact.

Step 4.2: Create Contact Groups (SmsNetwork → Groups)

  1. Expand SmsNetwork → Groups in the Nav tree.
  2. Drag SmsGroup from the palette and drop it into Groups (e.g., name it HVAC_Team or Night_Shift).
  3. Open its Property Sheet and expand Members: every contact in your address book automatically appears as a boolean checkbox!
  4. Set thecontacts that belong to this group to true and click Save.

6. Step 5 — Create Point Monitoring Rules (SmsPointRule)

Point rules watch any Niagara control point (BACnet, Modbus, KNX, OPC, Niagara Virtual, or internal writable points) and send SMS alerts when a condition is met — without needing to modify the point itself.

  1. Expand SmsNetwork → Rules in the Nav tree (you can also create sub-folders using SmsRuleFolder per building or system).
  2. From Palette → Rules, drag one of the rule templates into Rules:
    • SmsPointRule — Blank general-purpose rule
    • HighValueRule — Pre-configured for numeric high limit (> 30, deadband 1, 5-minute delay)
    • StateRule — Pre-configured for enum/boolean/string states matching Fault|Trip|Alarm
    • OfflineRule — Pre-configured for device/point communication loss (Status is Down for 2 minutes)
  3. Open the rule's Property Sheet and configure:
Property How to Configure
Source ORD Click the folder/component chooser icon and select the Niagara point to monitor (e.g., station:|slot:/Drivers/BacnetNetwork/Chiller1/points/WaterTemp).
Condition Choose from 16 built-in conditions:
  • Numeric: Greater than (>), Less than (<), Greater or equal (>=), Less or equal (<=), Outside range, Inside range
  • Boolean / Enum / Text: Value equals (=), Value not equals (!=), Is true / active, Is false / inactive, Any value change
  • Niagara Status: Status is Alarm, Status is Fault, Status is Down (offline), Status is Overridden, Status is Not OK
Compare Value Used by Value equals / not equals. Supports multiple values separated by | or , (e.g., Fault|Trip|Alarm, On, true, Unoccupied).
Limit / Low / High / Deadband Numeric thresholds and hysteresis deadband (the value must drop back by Deadband before returning to normal).
Active Delay How long the condition must stay true continuously before sending the alert SMS (filters out brief sensor spikes).
Repeat Interval & Max Repeats If the point remains in alarm, re-send a reminder SMS at Repeat Interval up to Max Repeats times (0 = send once).
Notify On Normal When true, sends Normal Text when the point returns to normal.
Alert Text / Normal Text Message templates supporting placeholders: {station}, {time}, {point}, {path}, {value}, {status}, {state}, {rule}, {condition}, {limit}, {low}, {high}, {compare}, {description}.
Recipients Expand Recipients and set the checkboxes to true for every Group (Group: ...) or individual Contact that should receive this rule's messages.
Testing a Rule Instantly: Right-click any SmsPointRule and select Actions → Send Test SMS. It will immediately read the live point value, render the template, and queue a test SMS to all selected recipients—even if the alarm condition is not currently active.

7. Step 6 — Using the Wire-Sheet SmsSender Block

If you build custom logic on a Wire Sheet (using `kitControl` logic blocks, schedules, or composites) and want a boolean trigger to send an SMS:

  1. Drag SmsSender from Palette → Rules onto SmsNetwork → Rules or onto any Wire Sheet anywhere in the station.
  2. Link any `BStatusBoolean` output slot to the Trigger input of SmsSender. Whenever Trigger transitions from false → true (rising edge), the configured Message is sent.
  3. Alternatively, link an action/event to the Send action, or link a dynamic string slot to the Send Text action.
  4. Expand Recipients on SmsSender and tick the contacts/groups that should receive the message.

8. Step 7 — Route Niagara Alarms to SMS (SmsAlarmRecipient)

To forward standard Niagara alarms from AlarmService to SMS contacts and groups:

  1. In the Nav tree, expand Station → Config → Services → AlarmService and open its Wire Sheet.
  2. From the root of the ignitechsSms palette, drag SmsAlarmRecipient onto the AlarmService Wire Sheet.
  3. Link the alarmEscalation1 (or alarmEscalation2) slot of your AlarmClass (e.g., defaultAlarmClass or CriticalAlarms) to the routeAlarm action on SmsAlarmRecipient.
  4. Double-click SmsAlarmRecipient to configure its Property Sheet:
    • Time Range / Days Of Week / Transitions: Standard Niagara alarm routing filters (e.g., To Offnormal, To Fault, To Normal).
    • Sms Network: Leave null (`BOrd.NULL`) to automatically use the station's `SmsNetwork`, or pick a specific `SmsNetwork`.
    • Recipients: Expand and set checkboxes to true for the Contacts and Groups that should receive alarms.
    • Alarm Text: Default {station} {state}: {source} - {msg} [{alarmClass}] {time}{ackHint}
    • Ack Text: Default {station}: {source} acknowledged by {user} {time}
Placeholder Replaced With (in SmsAlarmRecipient)
{station}Site Name configured on SmsNetwork (or Station Name).
{state}Alarm state in uppercase: OFFNORMAL, FAULT, NORMAL, or ACKNOWLEDGED.
{source}Alarm source name (sourceName facet or slot path).
{msg}Alarm message text (msgText facet, with Niagara lexicon tags resolved).
{value}Present value at the time of alarm (presentValue facet).
{alarmClass}Name of the Niagara Alarm Class.
{priority}Niagara alarm priority (1–255; also controls the SMS queue priority).
{ackCode} / {ackHint}Short numeric code (e.g., Reply ACK 104) for two-way SMS acknowledgement.

9. Step 8 — Monitoring, Diagnostics & Troubleshooting

Open the Property Sheet of SmsNetwork at any time to monitor real-time health:

  • Queue Size: Number of messages waiting to be sent or retried.
  • Total Sent / Total Failed: Cumulative delivery counters since station start or last reset.
  • Last Sent Time / Last Error: Timestamp of the last successful SMS and the most recent gateway error message (if any).
  • Activity: Live multi-line log (newest at top, last 50 events) showing every queued, sent, failed, or suppressed SMS and which gateway delivered it.
Symptom / Message Cause & Resolution
no reachable recipients in Activity log Ensure at least one Contact or Group is ticked (true) under the rule/alarm recipient's Recipients slot, the contact has a valid phone number, and the current time falls within the contact's On Duty Days and On Duty Time.
HTTP 401 or HTTP 403 on Gateway Verify the Username (Device ID / Account) and Password (API Key / Token) in the gateway's Property Sheet.
suppressed duplicate / queue full The exact same message text was already sent to that phone number within the Duplicate Suppression window (default 2 minutes). Lower Duplicate Suppression on SmsNetwork if testing repeated identical messages.
Contacts added later don't show in Recipients Adding/renaming a contact updates all checklists automatically when the station is running. If edited offline, right-click SmsNetwork and invoke Sync Recipients (or restart the station).
